# Engineering standards

The rules this project holds itself to, why each one exists, and what fails when you break it.
Read it before changing something; add to it when a rule earns its place.

It replaces the two standards documents that came before it — prompt-shaped, asking for a
generic layout and a big-bang reorganisation of a working codebase. They are in the history
rather than in the tree; the rules worth keeping are here, corrected where they were wrong and
with the reasoning the originals did not carry. This asks for the smallest change that
satisfies a rule, in the shape the project already has.

A rule's number is an identifier, not an order: rules are added, never renumbered, because
other documents cite them (the Makefile cites G3).

Two words are used precisely:

- **Enforced** — a command fails. The check is named, and it runs on every change (`make lint`,
  `make test`, `make cover`) or on a schedule (`make security`, `make mutations`).
- **Convention** — no check; it is held by review, and saying it is convention is honest about
  that rather than pretending otherwise.

## Working with an agent

Most changes here are made with one, so the rules assume it. Three instructions to give it, and
to follow yourself:

1. **Do not scaffold, and do not reorganise.** The layout below is deliberate; `mkdir`ing a
   generic tree or moving files into `domains/` and `infra/` is a change with no feature behind
   it, and it is the change most likely to break something.
2. **Make the smallest change that satisfies the rule.** If a rule and the existing code
   disagree, say which one should move before touching either.
3. **Run `make lint` and `make test` before saying it is done.** A change that has not run the
   tests has not been made.
4. **When the work is finished, run `/deslop`** (`.agents/prompts/deslop.md`). It is the review pass
   that removes what accumulated: abstractions nothing needed, defensive branches inside trusted
   code, comments that restate the code. It preserves behaviour, asks before removing anything
   significant, and validates with the commands above. Run it per work package, not as a
   periodic sweep of the repository — a large cleanup diff is a change nobody can review.

## The shape of the repository

```
gateway/cmd/acornd/     one binary, flags, wiring, logging, signals. Nothing else.
gateway/internal/control/  the domain: workspaces, conversations, defaults, resolution
gateway/internal/httpapi/  the transport edge: routes, auth, streaming
gateway/internal/protocol/ the wire types, mirrored by the worker
gateway/internal/workerpool/ one harness process: spawn, supervise, JSONL
gateway/web/               the built interface, embedded; generated by `make ui-build`
ui/                        the interface: React, tokens, Storybook
worker/src/                the harness adapter, one file per concept
worker/test/               unit tests, and the protocol contract
docs/adr/                  decisions, numbered, with the alternatives
docs/features.md           what it does, with the test that covers it
```

`internal/` is the default for Go. Nothing is exported for its own sake. The worker's files are
named after the concepts in the ADRs (`config.ts`, `hooks.ts`, `commands.ts`, `delegation.ts`,
`skills.ts`, `meta.ts`) because that is what makes them findable; a `domains/` and `infra/`
split would hide exactly that.

## Rules for everything

| # | Rule | Why | Check |
|---|---|---|---|
| S1 | A comment explains **why**, and names the failure it prevents. | The next reader has the same information as you: the bug, not the style. | Convention |
| S2 | No behaviour change without a test that **fails without it**. Reintroduce the bug and watch it fail. | A test that passes before and after proves nothing. | Convention for the writing, `make mutations PKG=…` for the proof: a mutant that lives is a test that ran and did not distinguish |
| S3 | A feature is listed in `docs/features.md` with the test that covers it. | The inventory is how anyone knows what "done" means. | Convention |
| S4 | A decision that is not obvious gets an ADR: context, alternatives, what was chosen. | Six months later the question is "why not the obvious thing". | Convention |
| S5 | Errors are loud at startup, returned at boundaries, and told to the model as results. | A silent misconfiguration is a support burden; a stack trace in a tool result is noise. | Convention, end-to-end |
| S6 | The protocol is defined once per language; change both in one commit. | `worker/src/protocol.ts` ↔ `gateway/internal/protocol/protocol.go` are one contract. | Convention |
| S7 | Storage is the truth, frames are complete views, a reconnect is safe. | The client must be able to throw its state away. | `TestTheStreamSendsStateViewsAndKeepalives` |
| S8 | One path for one thing: if a second entry point needs what the first does, extract it. | Recovery reimplemented start and got it wrong (a duplicate conversation, no model). | `make lint` → `make analyze` fails on a duplicated block; the extraction itself is Convention |
| S9 | An exception carries its reason on the same line — a lint disable, an entry in `.coverageignore`, a floor with a clause. | An unexplained `nolint`/`disable` is a rule losing quietly. | `make lint`, `make cover` |
| S10 | Coverage and mutation floors are **ratchets**: they may only move up, and a number that looks worse while the work under it grew says so next to the number. | A bar that can be lowered to make a run green is a wish. Efficacy is killed over *reachable* mutants, so covering new code lowers the ratio while nothing gets worse — the **killed count** is what may not fall. | `make floors` against `origin/main`, `make cover` (`FLOOR=0` reports without failing), `make mutations PKG=…` |
| S11 | A package that cannot reach the target says why **on its floor line**, and the report prints it as excepted rather than as work left to do. | An exception that reads like a to-do stops being exceptional, and a reason nobody writes down is a reason nobody can argue with. | `make cover` — `excepted at N%: …` |

## Go

### Layout and design

| # | Rule | Why | Check |
|---|---|---|---|
| G1 | `ctx` is the first argument, and the **lifetime** belongs to the owner. A request context never owns a goroutine. | A supervisor started with a request's context stops supervising when that request ends. | Convention |
| G2 | Interfaces are declared where they are consumed; constructors return concrete types. If there is one implementation and no test double, do not write the interface. | An interface invented for its own sake costs indirection and buys nothing. | Convention |
| G3 | Dependencies are passed explicitly. No package-level mutable state, and `init()` is not for setup. | Import order must not decide program behaviour. | `make lint` |
| G4 | Document the lock order on the struct, and take locks in that order. **Never hold a lock across I/O or a process call.** | Two orders for one pair of locks is a deadlock that only shows under a writer. | `internal/control/lockorder_test.go` |
| G5 | One owner per goroutine, and the owner cancels it. A supervisor must be idempotent: a duplicated "it died" signal must not start a second process. | A closed worker that restarted itself left two harnesses over one storage. | Convention, `TestABrokenWorkspaceFileIsReportedAndHeals` |
| G6 | `panic` is for the unrecoverable; `log.Fatal` and `os.Exit` live in `cmd/` only. | A library that exits takes the decision away from its caller. | Convention |
| G7 | `internal/` is the default; an exported identifier has a doc comment and a caller. | The public surface is a cost, not a status symbol. | `make lint` → `make analyze` fails on a symbol unreachable on both platforms (the feature suite is a second root); the doc comment is Convention |
| G14 | Ending the process is the entry point's decision: a signal or an explicit shutdown, cleanup once, in `cmd/`. A package returns an error and lets its caller decide. | A library that exits takes the decision away, and cleanup in five places means it happens in none of them reliably. | Convention |
| G17 | The layer table in ADR 0002 is the import graph: `cmd` may import `internal/*`, `httpapi` may not import `sandbox`, and `control` is the only package that knows both the edge and the engines. A new edge is a decision, and it is written into the row it belongs to. | The transport re-deriving a rule the domain owns is how `httpapi` came to import `sandbox` and validate an engine name itself. | `internal/arch/arch_test.go`, in `make lint` |

### Errors

| # | Rule | Why | Check |
|---|---|---|---|
| G8 | Wrap with `%w` where a caller can act on the cause; return as-is where wrapping adds nothing. | `errors.Is` works only if someone wrapped. | Convention |
| G9 | Never log an error **and** return it. | One failure, one report; double reporting trains people to ignore logs. | Convention |
| G10 | An ignored error is written as `_ =` and only where the reason is obvious: a `Close` on a read, a best-effort shutdown, a response whose failure the client already sees. Never for a write to storage, a commit, or a request. | `errcheck` bans the whole class and gets ignored; this bans the part that matters. | `make lint` → `make analyze` (`errcheck` and `staticcheck` through golangci-lint) |

### Tests

| # | Rule | Why | Check |
|---|---|---|---|
| G11 | A unit test lives in the package it tests and needs no process. A test that needs processes, ports, or a harness lives in `internal/e2e`, and one that needs an engine declares which with `maybeSandbox`, `workspaceResources`, or `notSandbox`. | The fast loop has to stay fast, or nobody runs it. | `make check`, `make test` vs `make test-sandbox` |
| G12 | Wait for a condition with a deadline, never for a fixed duration. | `time.Sleep(2 * time.Second)` is either slow or flaky, and often both. | Convention, review |
| G13 | `-race` is part of the suite, not a special occasion — including for the gateway the end-to-end tests spawn, which is a separate process and would otherwise be uninstrumented. | The bugs this project has had were concurrency bugs. | `make test` |
| G15 | A table when the test is the same check over different inputs, so the cases read as a list of situations rather than as prose. | `resolveThinking` and the defaults chain are only legible as a table; a name per case says what each one is for. | Convention, review |
| G16 | A test removes what it creates. A temp directory is scratch, not a record. | 384 had accumulated in `/tmp` before anyone looked, and the end-to-end harness left a built binary behind on every run — a `defer` before `os.Exit` never runs. | Convention, review |

## TypeScript / Bun

### Types at the edges

| # | Rule | Why | Check |
|---|---|---|---|
| T1 | `any` is banned; use `unknown` and check. | An `any` is a decision to stop knowing. | `typescript/no-explicit-any` |
| T2 | `as` is allowed only where a check immediately precedes it, or at a documented trust boundary. | The cast is the boundary; write down which side of it you are on. | `make lint` |
| T11 | The runtime's own tools and APIs first — `Bun.file`, `bun test`, `bun --watch`, `Bun.spawn`. A dependency needs a reason, which is why there is no validator library here: the payloads we parse are our own protocol (checked by shape) and files the user writes (checked field by field, with tests). | Every dependency is someone else's release schedule, and a validator earns its place against an untrusted, changing payload, not a pipe we control. | Convention, review |
| T3 | A union that grows must break every `switch` over it: `Exclude` the parts handled elsewhere, and make the default `never`. | A new protocol command silently became "unsupported" instead of a compile error. | `switch-exhaustiveness-check` |
| T4 | Strict compilation, including `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, and `verbatimModuleSyntax`. | `strict` alone still lets `array[0]` be a value that is not there. | `bun run typecheck` |

### Behaviour

| # | Rule | Why | Check |
|---|---|---|---|
| T5 | No floating promises: `await`, `return`, `.catch`, or an explicit `void` for something deliberately not awaited. | A rejected promise nobody holds is an invisible failure. | `no-floating-promises` |
| T6 | Side effects belong to the entry point. `config.ts`, `hooks.ts`, `commands.ts` are functions of their arguments. | It is why unit tests can cover the rules without a harness. | Convention |
| T7 | A misconfiguration is loud where it is read, naming the file and the field. | A guard without a reason must not become a guard that does nothing. | `worker/test/config.test.ts` |
| T8 | An error the model should see is a tool result, not a throw. An unexpected exception inside a command is an error response, not a process exit: the worker holds live runs, and staying up is the service it provides. | Throwing away a tool's explanation loses the only useful part, and a crash takes every conversation with it. | Convention |
| T9 | A store never hands out its own object; a task commits before it shows. | Mutation through a getter is the hardest bug to find. | `worker/test/skills.test.ts` |
| T10 | Serialise where order is the contract (`CommandQueue`), and say so where you do it. | Answers that overtake their questions is a race with a plausible-looking log. | `worker/test/protocol.test.ts` |

### The interface

| # | Rule | Why | Check |
|---|---|---|---|
| T12 | A design value comes from a token. Tailwind's default scales are unregistered — `p-13`, `bg-blue-500`, and `text-lg` produce no CSS — and arbitrary values (`p-[13px]`) fail. | A class that is not a token does not fail loudly, it ships unstyled: metricside's button used `text-[11px]` and `text-white` while its token file sat beside it. | `cd ui && bun run check:system`, in `make lint` |
| T13 | Screens are dumb and classless: they compose components and the layout primitives, and the app applies the logic. | A screen that styles or fetches cannot be rendered as a story, and the states nobody stories are the states that break. | `ui/scripts/check-system.ts`, in `make lint` |
| T14 | A component, and every state it can be in, has a story in Storybook, in light and in dark. | The catalogue is the design surface; "reviewed in Storybook" is only true if the state is there. | Convention, review |

The Foundations pages (`ui/src/foundations/`) are the catalogue's own: they display the primitive ramps with `var(--base-*)`, and `check-system` exempts them from T12's rule for exactly that reason. They are not a place to import from.

## Enforcement

`make lint` is the static half. It runs only what it finds installed, and says what is missing
rather than pretending to have checked:

| What | Command |
|---|---|
| Go formatting | `gofmt -l` |
| Go correctness | `go vet ./...` |
| Go beyond vet: complexity, duplication, dead code, error shape | `make lint` → `make analyze` → `golangci-lint` and `deadcode` (golangci-lint contains `staticcheck`; 2026.2+ for Go 1.27) |
| Go idioms | `make modernize` — deliberately not in `make lint`: it is the one Go check that costs seconds, and what it finds is drift, so a daily workflow runs it as a prompt rather than a gate |
| no `init()` in the gateway | a grep, because the rule is absolute |
| the layer table | `internal/arch/arch_test.go`, in `make lint` — G17 |
| TypeScript types | `bun run typecheck` |
| TypeScript rules | `bun run lint` (oxlint, type-aware through tsgolint) |
| TypeScript formatting | `bun run format:check` (oxfmt). `bun run format` writes twice on purpose: oxfmt 0.72 does not reach its fixed point in one pass when a signature carries a long inline object return type ([oxc#26240](https://github.com/oxc-project/oxc/issues/26240)). |
| Interface types, rules, and formatting | `cd ui && bun run typecheck`, `bun run lint`, `bun run format:check` |
| Interface design system | `cd ui && bun run check:system` — the source scan and the Tailwind probe behind T12 and T13 |
| Interface bundle | `make ui-build`, and `make test` runs it before the Go tests |
| lint and ignore exceptions have reasons | a grep |
| the console's behaviour in a real browser | `make ui-check` — it starts a gateway on the host engine, runs the suite, and stops it |
| commit message shape | `scripts/check-commits.mjs`, over a pull request's commits in CI |

`make check` is the fast loop (types and unit tests, ~6s). `make test` adds the end-to-end suite
against a real gateway — resource tests on the host engine, tests that need no engine against
the refusal path — under `-race` and `-shuffle=on` (~30s, no hypervisor needed). It also runs the
Go fuzz seeds, which is where the worker's `JSON.parse … as Command` crash on a bare `null` was
found. `make test-sandbox` is the microVM engine boundary: the live driver, the worker's SDK
suite, and the e2e tests that exercise execution and the mounts. `make tools` installs the
linters.

Five reports sit beside the gate, and a floor with no command that runs it is decoration:

| What | Command | Where it runs |
|---|---|---|
| coverage across both processes, merged, per package | `make cover` — fails below a floor; `FLOOR=0` reports without failing | `verify`, on every push |
| mutation efficacy per package | `make mutations PKG=./internal/control` — fails below a floor of efficacy **or** of killed mutants | `verify`, for the packages a change touches; weekly for all of them |
| the ratchet itself: no floor steps down | `make floors` — fails on a decrease, or on a floor line that disappears with its package still in the tree | `verify`, on every push |
| complexity, duplication, dead code, unreachable code | `make analyze` — **fails on any finding**; 0 today | `make lint`, so on every push |
| known vulnerabilities and the security rules staticcheck does not carry | `make security` — `govulncheck`, `make sast` | the `security` workflow, weekly and on a release tag |

Mutation testing is minutes per package, so a pull request pays for the packages its diff touches
and no others: `scripts/mutation-targets.mjs` maps changed files to the packages that have a floor
line, ranks them by changed lines, and takes the top two. A refactor spread over six packages
sweeps two of them and says which four it left, with the command that runs each. The weekly run
still covers all seven, because a package nobody changed can still lose an assertion to a
dependency.

The floors are the one standard that a pull request is most tempted to edit rather than meet, so
`make floors` compares both files with `origin/main` rather than with their own promise: a number
that moves down fails, and so does a floor line deleted while its package is still in the tree.

None of this is enforced by a machine unless it runs on every change: `.github/workflows/ci.yml`
runs on every push, in jobs that share one setup action (`.github/actions/setup`), and `verify` is
the fan-in that branch protection requires — a job added to the file is covered by the rule without
anyone editing the rule.

| Job | What it runs | Why it is its own job |
|---|---|---|
| `static` | `make lint` | a broken rule is worth knowing before a slow suite |
| `go` | `make test-suite COVER=1` | the Go suites **once**, instrumented, so the test verdict and the coverage floors come from one run |
| `worker` | `make js-test` | the harness and interface unit tests: seconds, and they need no bundle |
| `browser` | `make ui-check` | a real gateway and a real browser, which nothing else has |
| `commits` | `scripts/check-commits.mjs` | needs the commit range, not the tree |
| `floors` | `make floors` | compares the tree with the base branch, so it needs history and nothing else |
| `mutations` | `make mutations` for the packages the diff touches | minutes per package, bounded by `--max 2`, and skipped when the diff touches none |
| `sandbox` | `make test-sandbox` | boots real microVMs; the slowest and the only one that needs `/dev/kvm` |
| `bwrap` | `make test-bwrap` | real bubblewrap and pasta, and an image from a registry |

Every job above is a `needs` of `verify`, the two engine tiers included. They ran on every push
without being able to stop a merge until 2026-10-29, which is a gate that says the thing it was
asked not to.

`main` is protected: `verify` is required, administration is not exempt, and history cannot be
rewritten. A run that files something rather than failing it — a surviving mutant — opens an issue
with the report, because writing the test that kills it needs judgement and a pull request made
without any would be a guess with a green tick on it.

CI runs on GitHub's machines, which is what makes the sandbox tier a gate rather than an
occasional: a hosted runner exposes `/dev/kvm` once a udev rule makes it readable, so the tier that
boots real microVMs runs beside the fast ones instead of queueing behind them.

Nothing runs on the self-hosted box, and nothing asks for it. The one thing it bought was a
hypervisor, and the hosted runner has one; everything else it ran — the security checks, the daily
`modernize`, the release's four cross-builds — was paying for a single machine that runs one job at
a time. On 2026-10-29 that machine made a four-leg release take **1h43m** and a 16-second
`govulncheck` wait twenty minutes for its turn. The `sandbox` job still takes a `runner` input on a
manual dispatch, for the day the tier needs a machine with another hypervisor or another
architecture.

## The evidence

Every rule above with a bug behind it is here, because a rule with a story survives contact
with a deadline:

| The bug | The rule it produced |
|---|---|
| The gateway hung: the eviction sweep took the registry lock and then a control's, while a state build took them in the opposite order. | G4 |
| A workspace whose trust changed ran **two harnesses over one storage**: closing a worker did not stop its supervisor, and a death was announced twice. | G5 |
| A typo in a workspace's guard config took the whole gateway down, and the reason was only in the log. | S5, T7 |
| Recovery created a second conversation, landed on it, and skipped the settings a first start reads — so a workspace whose first start failed answered nothing. | S8 |
| A workspace that had never saved settings never read the install defaults. | S2 (the test that caught it) |
| `auth_answer` was handled before the command queue on purpose (queueing it would deadlock), so the switch looked incomplete. | T3 — the fix was to say it in the type, not to reorder the code. |
| The end-to-end cleanup removed every sandbox labelled `acornd` — every test's, not the finishing test's — so a parallel sandbox run failed in a different set of tests each time. | G16 |
| metricside's components invented `text-[11px]`, `px-2.5`, and `text-white` while its token file sat beside them, and nothing objected. | T12 |
| The registry's repair said it kept "the first" general workspace; the registry is a map, so which one survived was whatever the iteration produced, and the same file could open differently on two runs. | S2 — the test failed on its second run, which is what a map hiding an order looks like |
| `Close` stopped a workspace's worker and left `workerUp` true, so a list built after a shutdown said every workspace was still running. | G5 — one act, one flag: `stopWorker` had always cleared it |
| A message that was only files reached the worker without `text` (omitempty) and failed the whole send on `text.trim()`. | S6 — the field is optional on the wire, so the handler reads it as absent |
| The draft endpoint answered with the draft **and then the state**: two JSON documents on one response, which no client can parse. | S8 — the shared shape wrote an answer that belonged to one handler |
| The page routes' comment promised `index.html` for any unmatched path; the server answers 404, and a test asserting the comment is what found it. | S1 — a comment that is not true is a lie the next reader trusts |
| `Bwrap.Remove` deleted a running sandbox's files but left its supervisor, bubblewrap, and commands; the lifecycle test passed because `List` reads only configs, and two runs were still alive on a real machine. | G16, S2 — the test removed what it created, but not the processes it created |
| Nested pasta printed `Couldn't configure user mappings` and exited 0, so the probe called a network that never existed healthy. | S2 — an exit status is not the whole answer when the tool prints its own failure |
| `TestSatisfiedInstallIsQuiet` read `/dev/kvm` from the machine, so the fast tier failed in the very bwrap workspace this project develops in. | G11 — a unit test has to answer on the machine that runs it, and the machine fact belongs in the input |
| A binary upgrade adopted a running bwrap sandbox and never wrote the new config; the device grant only appeared after removing the sandbox by hand. | S2 — the config the next start reads is part of the state, and it was never refreshed |

## Convention (not enforced)

Named here so nobody mistakes them for guarantees: naming, comment quality, which decisions
deserve an ADR, keeping `docs/features.md` current, and the judgement that a rule does not
apply to a particular case. If a convention keeps getting broken, give it a check and move it
into a table above — which is what happened to commit messages (now `.agents/skills/conventional-commits`
and `scripts/check-commits.mjs`), to the layer table (now `internal/arch`), to dead code (now
`make analyze`), and to "a test that fails without the change" (now `make mutations`).
